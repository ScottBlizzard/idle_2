# 冻结 MoE 路由非可组合性：Stage E 工程门报告

日期：2026-08-28  
判定：**`ENGINEERING_PASS`**  
科学解释：**禁止**  
后续权限：**Stage D 尚未授权**

## 1. 报告结论

Stage E 的唯一结论是：冻结的 OLMoE 路由干预实现能够在单张 RTX 4090 上以零重放误差、零缓存差异和零确定性差异运行；加入真实 GSM8K/MATH-500 提示的生成吞吐量后，发现阶段与确认阶段的完整算力投影在 25% 保守余量下约为 `9.17 GPU h`，低于预注册的 `12 GPU h` 上限。

这不是 H1–H5 的证据。工程运行使用的 72 个路由条件和生成 pilot 均不得用于挑选有利层、路由、子群或阈值。当前预注册只授权 Stage E，因此本报告不能自动开启 Stage D。

## 2. 设计与审计边界

Stage E 分成两个互不冒充的部分。第一部分检查路由基数、标准路径重放、层边界缓存、重复运行确定性和干预吞吐量；第二部分只测量冻结生成配置下的 token 吞吐量。生成 pilot 不抽取答案、不评价正确率，也不读取任何路由效应，因此不能产生科学结论。

两次运行均在物理 GPU 7 连续独占空闲 180 秒后启动。项目没有使用 GPU 0–3，没有终止或修改外部进程，全部缓存、日志和结果均位于 `/mnt/sdb`。

## 3. 工程正确性结果

OLMoE 配置断言全部通过：16 个 Transformer 层、64 个路由专家、每 token 激活 8 个专家，机械映射得到测试层 3 和 5。8 条工程轨迹共运行 72 个标准、单层和联合路由条件。

| 工程门 | 观测值 | 阈值 | 判定 |
| --- | ---: | ---: | --- |
| 路由基数 | 全部保持 top-8 | 必须保持 | PASS |
| 标准重放最大误差 | `0.0` | `≤1e-4` | PASS |
| 缓存/非缓存最大误差 | `0.0` | `≤1e-4` | PASS |
| 重复运行最大误差 | `0.0` | `≤1e-6` | PASS |
| Stage E 初次运行用时 | `0.04150 GPU h` | `≤1 GPU h` | PASS |
| 独占 GPU 计时 | 是 | 必须 | PASS |

初次运行给出的干预投影为：发现阶段 `0.99791 h`，确认阶段代理 `2.39497 h`，合计 `3.39288 h`。

## 4. 生成吞吐量结果

pilot 使用 GSM8K test 与 MATH-500 test 各 2 道按稳定标识排序后的题目。每题使用冻结配置生成 4 个样本：temperature `0.7`、top-p `0.95`、top-k `0`、最多 768 个新 token。共测量 4 道题、16 次生成；实际生成长度为 157–425 token，平均 `264.69` token。

投影没有用平均速度，而采用四道题中最大的每 token 耗时 `0.0104836 s/token`，并把每个目标问题统一外推到最坏的 `4×768` token。结果如下：

| 投影组成 | GPU 小时 |
| --- | ---: |
| 发现阶段干预 | `0.99791` |
| 确认阶段干预代理 | `2.39497` |
| 发现阶段生成 | `1.14508` |
| 确认阶段生成代理 | `2.74820` |
| 两模型加载代理 | `0.04704` |
| 原始合计 | `7.33321` |
| 加 25% 余量 | **`9.16651`** |

`9.16651 < 12`，因此完整诊断算力投影门通过。两次 Stage E 的累计上界为 `0.09193 GPU h`，也低于 1 小时上限。

## 5. 必须保留的限制

第一，生成投影按每个数据集和模型恰好获得 64 条目标轨迹计算，没有估计“四次生成均错误”导致的额外问题数。因此即使以后单独授权 Stage D，也必须执行累计六小时硬停止；未达到 48 条正确轨迹时应判该 cell 不可采纳，不能补数据或降低标准。

第二，DeepSeek-V2-Lite-Chat 的时间使用 `2.4×` 代理，而非真机直接计时。25% 余量是工程缓冲，不是数学保证。

第三，干预工程使用的是手写短轨迹。其 72 个条件只验证代码路径，不能估计反转率、交互规律、匹配 null、预测器效果或算法收益。
