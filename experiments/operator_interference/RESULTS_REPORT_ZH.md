# 条件无关竞争算子干扰：确认性实验报告

日期：2026-08-27  
冻结种子：`20260827`  
确认集：54 个配对任务（108 条记录）  
绑定结论：**`NO_GO_STOP_CURRENT_SEED`**

## 一句话结论

当前 seed 不能继续扩展到 GameBench，也不足以支撑 ICLR 论文主张。Gemma 2 9B 在主措辞下出现了显著且可干预的竞争算子干扰，但该效应没有在独立措辞下达到预注册复现阈值；其余五个独立模型家族又没有达到基础任务能力门槛，因此既没有两个合格的负向家族，也没有预注册要求的异号正向家族。

这不是一次工程失败。完整实验成功地把一个“看起来很像论文”的现象压缩成了一个单模型、措辞敏感的局部信号，并依据事前规则停止继续追逐有利结果。

## 3. 最重要的局部信号：Gemma

Gemma 2 9B 是唯一达到诊断能力门槛的独立家族。它在主措辞 Pack A 上呈现了一个内部一致的干扰链条：

| 证据 | 结果 |
|---|---:|
| C：仅活动算子，配对准确率 | 81.5% |
| D：加入条件无关的竞争算子，配对准确率 | 63.0% |
| Pack A 的 D−C | **−18.5 个百分点** |
| 95% 配对区间 | [−31.5, −5.6] 个百分点 |
| Holm 校正后的 p 值 | 0.0388 |
| 难度 1/2/3 的 D−C | −27.8 / −5.6 / −22.2 个百分点 |
| 非活动算子执行率 C→D | 0% → 10.2% |
| 可由非活动算子解释的额外 D 错误 | 4/13，30.8% |
| 纠正干预 | 63.6% → 100%，+36.4 个百分点 |
| 反向错误注入 | 100% → 63.6%，−36.4 个百分点 |
| plain template 的 D−C | −25.0 个百分点 |

尤其重要的是，4 个原本错误且符合纠正条件的决策全部被救回；反过来注入错误算子状态又损坏了 4 个原本正确的决策。这说明 Pack A 中的 wrong-operator 状态不只是与错误相关，它对这些被选中的决策具有可操作的因果作用。

但该信号没有通过独立措辞复现：

- Pack B 的 D−C 只有 −5.6 个百分点，置信区间跨过 0；
- 它没有达到至少 −7 个百分点的阈值；
- 只保留 Pack A 效应幅度的 30%，低于要求的 70%。

因此最准确的表述是：**Gemma 在一种冻结措辞中存在可干预的竞争算子干扰，但没有证据表明它是对语义等价措辞稳健的模型机制。**

## 4. 为什么其他家族不能被当作反例或复现

预注册要求 C 条件配对准确率至少为 65%，否则模型在无竞争算子时都没有稳定掌握任务，D−C 就无法诊断“新增无关算子造成的干扰”。

| 模型 | C 配对准确率 | Pack A D−C | 是否可诊断 |
|---|---:|---:|---|
| Gemma 2 9B | 81.5% | −18.5 | 是 |
| Phi-4 mini | 44.4% | +1.9 | 否 |
| Qwen3.5-9B 正对照 | 38.9% | +5.6 | 否，且不能计入独立家族 |
| Llama 3.1 8B | 33.3% | −5.6 | 否 |
| Granite 3.1 8B | 29.6% | +1.9 | 否 |
| Mistral 7B v0.3 | 29.6% | −5.6 | 否 |
| OLMo 2 7B | 3.7% | +3.7 | 否 |

Llama 和 Granite 的过程干预能够改变部分决策，但这不能修复基础能力不足；OLMo、Phi 和 Mistral 也没有形成符合预注册方向与强度的完整过程链。把这些低基线模型按某个子组重新筛选会构成事后选择。

## 5. 非约束输出诊断的解释边界

非约束、native-template 诊断在多个模型上大量产生无效或截断输出；Gemma 的 C/D 严格 schema 有效率均为 0%，对应配对准确率也均为 0%。所以这个诊断没有观察到符号反转，但它本身不提供有信息量的复现证据。最终 NO-GO 不依赖这项诊断：即使忽略它，Gemma 仍因 Pack B 失败而不能计为负向家族。

## 6. 对研究路线的含义

当前可以保留的知识不是“竞争算子干扰已经成立”，而是三点：

1. 无关但可执行的规则确实能在至少一个模型/措辞组合中进入生成过程，并通过纠正和反向注入改变最终选择。
2. 这种效应对措辞非常敏感，不能从一个显著 cell 外推成模型家族层面的机制。
3. 当前任务对多数 7B–9B 指令模型过难，导致跨家族符号异质性的核心问题不可识别。

因此不应开始 GameBench 扩展，也不应继续在当前 prompt/task 周围扫参。若继续寻找 ICLR 方向，必须另立一个新的、与本 seed 有清晰概念距离的假设；新假设应先保证多个家族在无处理条件下可稳定完成任务，再检验一个真正跨表达方式稳定的干预效应。
